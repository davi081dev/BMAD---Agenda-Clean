# Quick Reference - Architecture Decisions\n\n**Project:** agenda-clean  \n**Last Updated:** 29 de abril de 2026  \n**Status:** ✅ Ready for Implementation\n\n---\n\n## 🏗️ 5 Core Architectural Decisions\n\n### 1️⃣ Frontend Stack\n```\nReact 18 + TypeScript (strict mode)\n↓\nVite (build tool, <500KB bundle)\n↓\nTailwind CSS + shadcn/ui (WCAG A accessible)\n↓\nReact Context (state management)\n```\n\n**Why?**\n- Fast HMR for development\n- Small bundle (Ana's mobile)\n- Built-in accessibility\n- Simple state management for MVP\n\n**Commands:**\n```bash\nnpm create vite@latest agenda-clean-web -- --template react-ts\nnpm install -D tailwindcss postcss autoprefixer\nnpx tailwindcss init -p\n```\n\n---\n\n### 2️⃣ Backend Stack\n```\nNode.js 18+ LTS\n↓\nExpress.js (REST API)\n↓\nTypeScript (strict mode)\n↓\nPrisma ORM (type-safe queries)\n↓\nPostgreSQL (reliable, ACID)\n```\n\n**Why?**\n- Lightweight, proven framework\n- Type safety prevents bugs\n- Prisma handles migrations and schema\n- PostgreSQL prevents double-bookings (unique constraint)\n\n**Commands:**\n```bash\nmkdir agenda-clean-api && cd agenda-clean-api\nnpm init -y\nnpm install express cors dotenv passport passport-google-oauth20 @prisma/client\nnpm install -D typescript @types/express ts-node nodemon\nnpx prisma init\n```\n\n---\n\n### 3️⃣ Authentication\n```\nGoogle OAuth 2.0\n↓\nPassport.js (handles flow)\n↓\nJWT token (stateless)\n↓\nhttpOnly secure cookie (XSS-safe)\n```\n\n**Why?**\n- Zero friction (no passwords)\n- Industry standard\n- httpOnly prevents XSS attacks\n- JWT enables stateless backend\n\n**Admin Detection:**\n```\nFIRST LOGIN:\n  email === ADMIN_EMAIL ? role = \"admin\" : role = \"client\"\nCONFIG:\n  ADMIN_EMAIL=davi@example.com  (or company email later)\n```\n\n---\n\n### 4️⃣ Email Delivery\n```\nSendGrid API (reliable)\n↓\nAsync database queue (no blocking)\n↓\nBackground job (polls every 10 seconds)\n↓\n3 retries (handles transient failures)\n```\n\n**Why?**\n- Ana sees success instantly (no 30s wait)\n- Email queues asynchronously\n- Retries handle SendGrid timeouts\n- Database polling is simpler than Redis\n\n**Flow:**\n```\n1. POST /agendamentos → Create booking\n2. Queue email job in database (instant)\n3. Return success to Ana immediately\n4. Background job sends email later\n5. Ana receives confirmation within 30 seconds\n```\n\n---\n\n### 5️⃣ Double-Booking Prevention\n```\nDatabase Constraint (atomic)\n↓\n@@unique([date, time]) in Prisma schema\n↓\nPostgreSQL enforces at INSERT time\n↓\nApplication returns 409 if conflict\n```\n\n**Why?**\n- Atomic at database level (can't fail)\n- No race conditions possible\n- Reliable and performant\n- No application-level complexity\n\n**Schema:**\n```prisma\nmodel Agendamento {\n  id Int @id @default(autoincrement())\n  date DateTime\n  time String\n  // ... other fields\n  @@unique([date, time])\n}\n```\n\n---\n\n##
